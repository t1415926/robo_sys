# 初学者概念说明

本文从概念层面说明当前机器人导航项目在做什么，以及各个模块之间如何配合。

## 1. 机器人导航在解决什么问题

机器人要自主移动，通常需要回答四个问题：

```text
我在哪？
周围地图是什么样？
我要怎么走？
底盘应该怎么动？
```

对应到系统中就是：

```text
定位
地图
路径规划
轨迹跟踪与底盘控制
```

## 2. 地图是什么

当前项目中有两类地图。

### 3D 点云地图

3D 点云地图来自激光雷达建图，里面保存的是空间中的大量点：

```text
x, y, z
```

它更接近真实世界，可以表达墙、货架、地面、障碍物的三维形状。

在当前项目中，PointLIO 会生成或使用这种点云地图。

### 2D 栅格地图

2D 栅格地图是给导航规划用的地图。它把地面切成一个个小格子，每个格子表示：

```text
可通行
不可通行
未知
```

Nav2、A* 这类路径规划更适合使用 2D 栅格地图。

所以当前项目会把 3D 点云地图投影成 2D 栅格地图。

## 3. 为什么需要两张地图

3D 点云地图适合定位，因为雷达看到的是三维环境。

2D 栅格地图适合规划，因为地面机器人只需要在平面上走。

可以理解为：

```text
3D 点云地图：帮助机器人知道自己在哪
2D 栅格地图：帮助机器人知道哪里能走
```

前提是两张地图必须在同一个 `map` 坐标系下对齐。

## 4. 定位是什么

定位就是机器人判断自己在地图中的位置。

当前项目使用 PointLIO 做定位。它会对比：

```text
当前雷达看到的点云
已有的先验点云地图
```

然后估计机器人在 `map` 坐标系中的位置和朝向。

定位成功后，系统会知道：

```text
机器人现在在 map 中的 x, y, yaw
```

其中：

```text
x, y：机器人在平面地图中的位置
yaw：机器人车头朝向
```

## 5. 先验地图初始化是什么

机器人刚启动时，不一定知道自己在地图哪里。

先验地图初始化就是告诉机器人：

```text
这里有一张以前建好的点云地图
你大概从这个位置启动
你可以在附近搜索一下自己的准确位置
```

当前 PointLIO 主要搜索：

```text
x 方向偏移
y 方向偏移
yaw 朝向偏移
```

对于地面机器人，pitch 和 roll 通常由 IMU 重力方向处理，不作为主要搜索量。

## 6. 路径规划是什么

路径规划负责从当前位置到目标点找一条路线。

例如：

```text
当前位置：A
目标点：B
地图中有障碍物
```

规划器要找出一条不撞障碍物的路径。

当前项目中已经实现了一个 A* 全局规划器。

A* 会读取 2D 栅格地图，然后输出一条路径：

```text
/plan
```

这条路径是一串地图坐标点。

## 7. 为什么还需要轨迹跟踪

路径规划只告诉机器人“应该走哪条线”，但不会直接控制电机。

机器人还需要一个轨迹跟踪模块，把路径变成速度指令。

速度指令通常是：

```text
linear.x   前进速度
angular.z 旋转速度
```

在 ROS 中，这个话题叫：

```text
/cmd_vel
```

当前项目使用 Nav2 controller 跟踪路径，并输出 `/cmd_vel`。

## 8. 底盘如何运动

底盘驱动接收 `/cmd_vel`，然后控制电机。

对于差速底盘，主要使用：

```text
linear.x   前进或后退
angular.z 原地或行进中转向
```

差速底盘不能像全向底盘那样横向平移，所以当前系统已经按差速底盘约束进行了调整。

## 9. 局部避障是什么

全局地图通常表示固定环境，比如墙、货架、固定障碍物。

但真实环境中会出现临时障碍物，比如：

```text
人
临时放置的箱子
其他移动设备
```

这些不应该直接写死到全局地图里。

所以系统使用 local costmap 处理实时障碍。

当前项目中，PointLIO 发布当前帧点云：

```text
/cloud_registered_body
```

Nav2 local costmap 会订阅它，用来标记机器人附近的实时障碍。

## 10. 全局地图和局部地图的区别

可以这样理解：

```text
全局地图：
  稳定、长期使用
  用于规划大方向

局部地图：
  实时、短期有效
  用于避开附近临时障碍
```

所以不要轻易把动态障碍实时写入全局地图。

更合理的方式是：

```text
全局地图保持稳定
局部 costmap 处理动态障碍
```

## 11. 当前项目的完整数据流

整体链路可以理解为：

```text
真实雷达 / bag 数据
  -> PointLIO
  -> 机器人在 map 中的位置

先验点云地图
  -> PointLIO 定位参考

2D 栅格地图
  -> A* 全局路径规划
  -> 路径 /plan
  -> Nav2 controller 轨迹跟踪
  -> /cmd_vel
  -> 底盘运动

当前帧点云
  -> local costmap
  -> 实时局部避障
```

## 12. 当前项目已经具备什么能力

目前已经具备一个基本导航闭环：

```text
有地图
能定位
能规划路径
能跟踪路径
能输出 /cmd_vel
能接入底盘
能显示在 RViz 中
```

下一步重点不是再加很多新模块，而是把真实场地中的参数调准确：

```text
点云地图路径
2D 栅格地图 origin 和 resolution
初始位置 prior_T
初始朝向 yaw_range
障碍膨胀距离
底盘速度限制
TF 外参关系
```

## 13. 初次实车测试建议

不要一开始就让机器人跑远距离。

建议顺序是：

```text
1. 确认雷达和 IMU 数据正常
2. 确认 PointLIO 能定位
3. 确认机器人在 RViz 中的位置正确
4. 确认 2D 地图和机器人位置对齐
5. 给 0.5 到 1 米的小目标
6. 观察是否生成路径
7. 观察 /cmd_vel 是否正确
8. 低速测试底盘方向
9. 再逐步增加距离和转弯
```

核心原则：

```text
先看得懂
再跑得慢
最后跑得稳
```
